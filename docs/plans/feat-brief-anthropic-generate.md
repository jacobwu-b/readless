## Branch

`feat/brief-anthropic-generate`

## What

Add `lib/anthropic.ts` (server-only Anthropic client from the config layer) and
`lib/generate.ts#generateBrief(title, author?)`, which streams Claude Opus 4.8 with adaptive
thinking, then JSON-parses and `Brief`-validates the response, returning a typed `Brief` or throwing
a typed error.

## Files

- `package.json` — bump `@anthropic-ai/sdk` `^0.70.0` → `^0.104.2`.
- `package-lock.json` — regenerated by `npm install`.
- `docs/decisions/0004-anthropic-sdk-adaptive-thinking.md` — ADR for the bump (create).
- `lib/anthropic.ts` — export a configured `Anthropic` client keyed from `config.ANTHROPIC_API_KEY`; server-only (create).
- `lib/generate.ts` — `generateBrief` + `BriefGenerationError` (create).
- `lib/generate.test.ts` — unit tests with the model boundary mocked (create).

## Approach

- `lib/anthropic.ts`: `export const anthropic = new Anthropic({ apiKey: config.ANTHROPIC_API_KEY })`. No SDK calls leak outside `lib/`.
- `generateBrief(title, author?, client = anthropic)` builds the system prompt via `buildBriefPrompt`, then `client.messages.stream({...}).finalMessage()` with `model: "claude-opus-4-8"`, `thinking: {type:"adaptive"}`, streamed for headroom. `client` is typed as a narrow structural interface so tests can mock just `messages.stream(...).finalMessage()`.
- Handle `stop_reason === "refusal"` first; collect text blocks; `JSON.parse` (→ `invalid_json` error); `BriefSchema.safeParse` (→ `schema_validation` error). Each failure is logged via the project logger and rethrown as a typed `BriefGenerationError` with a discriminant `code`.

## Tests

`lib/generate.test.ts`, model boundary mocked (a fake client returning a canned `finalMessage`):
- returns a typed `Brief` for a valid model response (reuse a well-formed fixture like `schema.test.ts`).
- throws `BriefGenerationError` `code: "invalid_json"` when the model returns non-JSON text.
- throws `BriefGenerationError` `code: "schema_validation"` when JSON parses but fails the schema.
- passes `title` and `author` into the prompt (assert on the captured `stream` params' `system`).
- edges: `stop_reason: "refusal"` → `code: "refusal"`; empty text → `code: "empty_response"`.

## Manual steps

- `npm install` to apply the dependency bump and regenerate the lockfile (documented in the PR).
- No new env vars (`ANTHROPIC_API_KEY` already in `.env.example` and `lib/env.ts`).

## Full-plan additions

### Blast radius

- Consumers: `J-103` (`POST /api/generate`) will call `generateBrief` and inherit the bumped SDK.
- Schemas: none changed — reuses the `Brief` schema from `lib/schema.ts` as-is.
- Public types: exports `generateBrief`, `Brief` (re-export not required), `BriefGenerationError`, `BriefErrorCode`.
- Runtime: introduces the first live Anthropic call path (server-side only). Streaming + adaptive thinking; max_tokens headroom to avoid truncation.
- Observability: failures logged via `lib/logger.ts` with `code` + `title` context (no secrets, no full model output).

### Risks / open questions

- SDK behavioural drift across 0.70 → 0.104 — caught by typecheck/build; runtime exercised only behind mocks in this PR (real call lands in `J-103`).
- Truncated output → invalid JSON. Mitigated by streaming + generous `max_tokens`; surfaces as the typed `invalid_json` error rather than a crash.
- Model wrapping JSON in prose/fences would fail `JSON.parse`; acceptable as a typed error for the MVP (prompt already says JSON-only).
